# Run the decision-layer demo

The public demo takes **already calculated price, volume and residual-mix effects** and turns them into management commentary, slide subtitles and traceable driver evidence. It uses the reviewed narrative module with invented inputs. It does not implement the production source-system ingestion, full PVM calculation, PowerPoint generation or live Empower connection.

## Run locally

Use Python 3.11 or 3.12:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python demo.py
python -m pytest -q
```

On Windows, activate with `.venv\Scripts\activate` instead. Runtime dependencies are limited to pandas; pytest is needed for validation. The CI workflow runs the demo and tests on both Python versions.

To try another invented scenario without overwriting the checked-in outputs:

```bash
python demo.py --input examples/input/synthetic-pvm.json --output /tmp/cm1-demo
```

The input must declare `synthetic: true` and `units: "kEUR"`. Monetary amounts must be finite numbers, every row must have country, segment and product labels, and each supplied PVM decomposition must match its CM1 change within 0.01 kEUR. Invalid inputs are rejected before reports are written. This consistency check does not independently prove that upstream PVM effects were calculated correctly.

## Inspect the results

| Output | What it demonstrates |
| --- | --- |
| [Management commentary](../examples/generated/management-commentary.md) | Four unedited machine-generated stories and slide subtitles: three countries and their region. |
| [Evidence JSON](../examples/generated/evidence.json) | Driver classifications, selected hierarchy paths, gross same-sign concentration, opposing contributions, policy settings and reconciliation gaps. |
| [Reporting feed CSV](../examples/generated/reporting-feed.csv) | One row per reporting scope with numeric effects, subtitle and story. It opens in Excel and supports downstream reporting adapters. |
| [Excel reporting exhibit](../examples/generated/reporting-feed.xlsx) | A formatted, packaged illustration of fixed reporting cells, using exactly the same synthetic stories and figures. |

`demo.py` regenerates the **Markdown, JSON and CSV** files. The XLSX is a packaged illustration and is **not rebuilt by this Python command**. It has no macros, external workbook links, PowerPoint connections or live Empower links. Editing its numbers does not rerun the narrative engine. The portfolio slide examples use a separate synthetic dataset and are not regenerated by this demo.

The workbook contains `Region`, `Country A`, `Country B` and `Country C` sheets. Each follows the same reporting contract:

| Cells | Purpose |
| --- | --- |
| `A3` | Complete generated management commentary. |
| `B5` | Generated slide subtitle. |
| `A8:B12` | Numeric price, volume, residual mix and total CM1 chart feed. |
| `D8:F16` | Supporting attribution and reconciliation evidence. |

In the original project, stable Excel reporting cells and chart ranges supported updates through Empower into PowerPoint. This exhibit makes that design tangible without publishing an organization-specific template or connection.

## Three decisions worth examining

1. **Country A: descend only as far as the evidence supports.** Price improves by 1,000 kEUR. Product A1 contributes 700 kEUR, so the story reaches the product level at 70% of gross price gains. The volume offset is spread across products, so its explanation stops at Segment A.
2. **Country B: a small net result can conceal the main story.** The country improves by just 20 kEUR, but Segment C gains 400 while Segment D loses 380. Each individual product is below the divergence threshold. The engine highlights both segments instead of dismissing the country as immaterial or choosing an unsupported product.
3. **Country C: attribute each effect to the right product.** Volume gains of 800 kEUR face price pressure of 600 and negative residual mix of 50. The volume leader is Growth product; the price-pressure leader is Price product. Ranking products by total change alone would miss that distinction.

The regional report retains country identity throughout its hierarchy. Products with the same name in different countries therefore remain separate when explaining opposing contributions.

## Input and policy

The [synthetic input](../examples/input/synthetic-pvm.json) contains 13 additive product records. `Base_CM1` is the current synthetic value and `Comp_CM1` is its comparison value. `Price_Segment`, `Volume_Segment` and `Mix_Segment` are supplied effects in kEUR, even on product-level records; these names preserve the reviewed module's existing interface.

The [policy file](../config/narrative_policy.json) makes the decision thresholds explicit. Defaults require at least 25 kEUR and 60% of gross same-sign contribution to descend the hierarchy. Material opposing branches require 150 kEUR and 25% of their gross signed side. These are configurable reporting judgments, not universal accounting rules.

Residual mix is described as an arithmetic residual. The generated text does not claim that it proves a commercial cause such as customer behavior or a product substitution.

## Validation

The 49 tests comprise 31 narrative contracts and 18 demo-boundary cases. They check material opposing effects, duplicate aggregation, hierarchy stopping rules, country separation, reconciliation exclusions, deterministic output ordering, exact story preservation across exports and rejection of incomplete or inconsistent inputs. The tests assess the decision layer and the demonstration, not confidential source-system refreshes or live presentation integrations.
